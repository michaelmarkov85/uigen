name: sparse-comments
description: User prefers minimal comments in code — only for genuinely complex logic
metadata:
  type: feedback
---

Use comments sparingly. Only comment complex code. Do not add explanatory comments to straightforward code, obvious logic, or self-documenting function/variable names.

**Why:** User finds excessive comments noisy and prefers clean, readable code.

**How to apply:** When writing or editing code, omit comments unless the logic would be genuinely hard to understand without them (e.g., non-obvious algorithms, tricky edge cases, workarounds with non-obvious reasons).
